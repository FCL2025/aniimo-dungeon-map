# 0.2.9 覆蓋地圖快捷鍵

使用 **F1**。使用者提供的遊戲按鍵設定圖中，F8 是「一鍵快照」，F1 未列出綁定。

1. 先在主視窗開啟「地圖模式」。
2. 遊戲中按 F1，暫時隱藏覆蓋地圖，便可點擊原本被遮住的位置。
3. 再按 F1 恢復。視窗相對位置、地圖縮放、平移、選取標記、篩選及圖示大小均保留，辨識與追蹤繼續運作。

主視窗最小化時也有效，長按只切換一次。手動隱藏後，遊戲移動、最小化或還原都不會自行解除隱藏；恢復時不取得焦點。按主視窗「地圖模式」或覆蓋視窗的 × 是完全關閉，會釋放 F1；之後需先按「地圖模式」才能再次使用快捷鍵。F1 只在覆蓋視窗存在期間註冊，包含暫時隱藏期間。

主視窗按鈕顯示「地圖模式：開 · F1」或「地圖已隱藏 · F1」。若 F1 被其他程式註冊，提示「F1 無法使用」，按鈕的滑鼠提示也保留原因；地圖仍正常開啟，可使用原本的按鈕關閉。

## 實作

`app/src-tauri/src/overlay.rs` 的跟隨執行緒使用 Win32 `RegisterHotKey(NULL, ..., MOD_NOREPEAT, VK_F1)` 與 `WM_HOTKEY`。不依賴 WebView 焦點、地圖辨識開關或遊戲擷取迴圈。按鍵訊息翻轉該覆蓋視窗的 `paused` 狀態，再由既有跟隨迴圈統一決定可見性，以免下一次跟隨更新把手動隱藏的視窗重新顯示。隱藏使用 `ShowWindowAsync(SW_HIDE)`，恢復使用 `SW_SHOWNOACTIVATE`；不重建視窗、不變更追蹤，也不改使用者偏好。

關閉時會等待執行緒結束，在原註冊執行緒解除 F1，避免立刻重開時殘留按鍵註冊。註冊失敗會把系統錯誤傳回主視窗，使用者仍能操作覆蓋地圖。行為依據 [Microsoft RegisterHotKey 文件](https://learn.microsoft.com/zh-tw/windows/win32/api/winuser/nf-winuser-registerhotkey)；`MOD_NOREPEAT` 避免按鍵自動重複造成連跳。

## 驗證

2026-09-26，以正式 0.2.9 EXE 的相同 SHA-256 副本、隔離 profile 和螢幕外原生 Aniimo.exe 測試視窗驗證，未修改使用者設定或移動使用者遊戲。

- Rust 16 項測試通過，包含手動隱藏優先於遊戲最小化／還原的判斷。
- 透過真正的 Win32 鍵盤輸入觸發 F1，覆蓋視窗 `IsWindowVisible` 由 true → false → true，同一 HWND、位置與尺寸保留。當時前景為使用者的伊莫視窗，切換前後焦點不變；覆蓋視窗本身使用螢幕外測試視窗驗證。
- 連續 12 個 F1 keydown 再 keyup 只切換一次。
- 手動隱藏後將測試遊戲最小化再還原，覆蓋仍保持隱藏；再按 F1 正常恢復。
- 主視窗最小化期間，F1 可隱藏及恢復。
- 透過 agent-browser／WebView2 確認主視窗顯示隱藏狀態、暫時隱藏沒有寫入或改變偏好，覆蓋 WebView 未重載；縮放、平移、選取標記、篩選、圖示大小保留，受控人物位置更新持續同步。
- 先由測試程序占用 F1，確認顯示 Windows 1409 衝突提示，覆蓋地圖仍可使用。解除占用、關閉再重開覆蓋後恢復正常。
- 完全關閉覆蓋會釋放 F1，可立即重新註冊。主視窗正常關閉時一併結束覆蓋、釋放 F1。
- 原生前端通過原有 31 張地圖／62 組難度篩選及圖示大小檢查。

本次未重新量測真實遊戲人物定位，也未驗證獨佔全螢幕覆蓋。F1 在使用者自訂綁定或其他工具設定不同時仍可能被占用。

## 重跑

```powershell
./scripts/build_portable.ps1
cd app/src-tauri
cargo test --release --locked
```

原生測試先將 EXE 複製到 `app/smoke-run-hotkey-0.2.9/`，依桌面版 README 使用 `--hidden`、隔離 `ANIIMO_TEST_DATA_DIR` 和 CDP 埠。另設定 `ANIIMO_TEST_SHOW_OVERLAY=1`，讓覆蓋視窗的真實顯示／隱藏邏輯可在螢幕外 fixture 上驗證，主視窗仍隱藏。此環境變數只影響 `--hidden` 測試啟動。

`scripts/tests/overlay-game-fixture.rs` 編譯成測試目錄內的 `Aniimo.exe`。以 `Start-Process -WindowStyle Hidden` 啟動，再用原生 API 在螢幕外顯示 fixture，並在測試主視窗選定其 HWND，避免作用於使用者遊戲。

使用 `overlay-hotkey-browser.js` 的 setup／remember／hidden／restored／conflict 階段檢查 UI，搭配 `overlay-hotkey-tools.ps1` 的原生按鍵、可見性及註冊檢查。測試工具只接受隔離目錄內的程序，未註冊 F1 時拒絕傳送按鍵。

機器可讀結果：`dist/hotkey-verification-0.2.9.json`。截圖：`app/smoke-run-hotkey-0.2.9/main.png`。
