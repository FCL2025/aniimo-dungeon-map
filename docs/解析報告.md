# 搶蛋大作戰：惡夢／混沌資料解析

解析日期：2026-09-25。來源為本機遊戲資源版本 `3595896`。

可以直接開啟 [點位檢視器](../exports/grab-eggs-data/index.html)，切換惡夢／混沌地圖池的 7 張地圖、獎勵類型及寶箱品質。原始解析仍保留 31 張底圖資料；地圖支援縮放、拖曳與點選來源。

本次完成的是離線設定與候選座標解析。尚未連接遊戲畫面、辨認當前地圖、追蹤角色位置或製作桌面置頂視窗。

工具範圍已限定為地城內的惡夢／混沌。檢視器只載入 `grab-eggs-dungeons` 的單張底圖；`grab-eggs` 外部地圖與額外分層貼圖只保留為調查檔案。怪物標記僅收錄首領級幽黯星法師。

## 座標如何得到

1. 每張圖的房間紀錄提供 `position`、`yaw`、`sandboxIds`。
2. `sandboxIds` 連到共用場景 10000 的物件群組；`scene_entity_data` 中的 `ResourceBox` 再連到獎勵類型。
3. 將物件的房間局部座標旋轉、平移，得到世界座標。
4. 使用遊戲自己的兩點校準設定，轉成 2048 × 2048 地圖像素。

對局部座標 `(x,y,z)`、房間原點 `(ox,oy,oz)`、角度 `θ = yaw`：

```text
worldX = x*cos(θ) + z*sin(θ) + ox
worldY = y + oy
worldZ = -x*sin(θ) + z*cos(θ) + oz

pixelX = (worldX - PointA.x) * (MapB.x-MapA.x)/(PointB.x-PointA.x) + MapA.x
pixelY = -((worldZ - PointA.z) * (MapB.y-MapA.y)/(PointB.z-PointA.z) + MapA.y)
```

最後的負號把遊戲 UI 的負向 y 轉成 PNG 向下的 y。座標對應完整原尺寸圖片，**不能直接用在 `_cropped.png` 上而不扣掉裁切偏移**。

數值運算與 `Common/Utils/RandomMapBatchUtils.lua`、`MapCoordUtils.lua` 的靜態指令相符，並已使用圖片疊點與入口／出口對照核對方向。沒有執行遊戲 Lua。

`digong_config_data` 中的組合 ID 可拆成房間 ID 與原始物件群組 ID。本版本計算為 `(sourceId % 2147483647) * 100 + roomId`。31 張圖的 62 個入口／出口引用皆能回連到對應房間與標記。

### 首領級幽黯星法師

使用者指定的怪物對應 `puppet_data[11001200090]`，繁體名稱為「首領級幽黯星法師」，英文名稱為 `Umbral Omega Stellarys`，`monsterType = 2`。解析器以此 ID 限定怪物，並核對物種與首領設定；不收錄一般星法師、花芽蟹或其他怪物。

目前共 108 筆首領候選，惡夢／混沌各 54 筆。其中 45 筆由地圖直接引用，63 筆依房間模板補充。它們受蛋巢模組與生成群組抽選影響，不能據此認定當場必定存在。輸出保留 `spawnGroupCandidates` 的群組 ID 與原始權重，但不將權重換算成未驗證的最終出現率。

檢視頁以藍色星形標示，提供「首領級幽黯星法師」獨立開關。星法師的英文物種名稱是 Stellarys；Prismana 在本機本地化資料中對應虹彩型態，並非這個首領的名稱。

### 樓層顯示與辨識

目前採用單張平面底圖，不做樓層切換。候選點保留世界座標的高度，但顯示時投影到 x/z 平面；這並非將某個高度以上的點刪除，也不宣稱底圖只代表一樓。

已檢查 `map_layer_level_data`、`map_level_config_data`、`map_level_config_load_data`：三表皆沒有這 31 張地城的直接設定；外部場景 3005 有樓層設定，不能直接套用到地城。

僅憑同一個平面座標無法唯一判斷上下樓層。若遊戲小地圖在不同樓層呈現不同輪廓、樓層文字或切換圖示，後續可利用畫面特徵，再配合進出樓梯的移動歷史推估；若畫面完全相同，外部影像辨識就無法可靠區分。尚未取得實機畫面驗證，因此目前維持單圖模式，沒有自動猜測樓層。

### 為何需要房間模組補充點

部分 `Scene.200xx.scene_room_data` 保存的群組清單，沒有共用房間模板後來出現的混沌蛋巢等項目。直接使用地圖清單會漏掉這些候選。

本次保留原始清單，另以相同 `resId`（房間 prefab）和群組集合做匹配。只有集合交集比至少 0.7、最佳候選無歧義時，才加入模板中額外存在的群組。相同 prefab 可能有不同鑰匙房版本，所以沒有直接合併所有同名模板。

補充結果是**推論**，並非已證明的遊戲執行時配置。正式檢視頁與桌面程式只對首領級幽黯星法師顯示同房間模板的補充候選點，讓混沌難度與缺少直接引用的房間也能看到首領可能位置；其他補充點仍不顯示。介面沒有補充點開關。原始 JSON／CSV 保留 `provenance`（`scene_reference`、`template_supplement`）供查核；匹配細節保存在 `validation.json` 的 `templateMatches`。

4 個群組 ID 被地圖引用，但在共用群組、生成器及物件表找不到對應紀錄：

```text
91144958, 91145818, 91145853, 91327625
```

共涉及 11 張地圖、27 次引用。可能是殘留設定或未包含於此用戶端的資料；目前無法確定原因，因此沒有補造位置。檢視器的「資料與限制」會指出當前地圖的缺口。

## 惡夢／混沌的生成差異

`digong_reward_data` 提供獨立的房間及通道設定：

| 設定欄位 | 惡夢房間 | 混沌房間 | 惡夢通道 | 混沌通道 |
| --- | ---: | ---: | ---: | ---: |
| EggCount | 1 | 1 | — | — |
| EggProbability | 0.15 | 0.25 | — | — |
| G-All | 7 | 7 | 5 | 5 |
| G0 | 0 | 0 | 0 | 0 |
| G1 | 0 | 0 | 8 | 8 |
| G2 | 6 | 6 | 4 | 4 |
| G3 | 4 | 5 | 2 | 3 |
| G4 | 2 | 3 | 0 | 0 |
| G5 | 3 | 4 | 0 | 0 |
| G6 | 1 | 2 | 0 | 0 |

這些是原始設定值，不能把 `EggProbability` 直接解讀為每個地圖像素／每一個蛋巢實體的最終出現機率，也不能將 G 值當成各點的已知機率。

靜態程式可見先組織合資格房間、依深度進行抽選，再處理額外蛋巢與獎勵群組。`sandBoxConfigType = 4` 的蛋巢群組會按 `sandBoxLevel` 選用對應難度，因此檢視器能切換 5／6 的蛋巢候選。其他特殊房間的固定配置也可能有蛋巢，仍受該場房間配置與關卡條件影響。

寶箱的 G0–G6 群組、房間抽選、圖形關卡觸發、生成器條件都尚未完整重建。因此目前不假裝切換難度後就知道哪些寶箱已生成，而是保留候選與原始群組值。可以先據此製作各類獎勵的顯示開關，再用實際場次校準。

## 解碼器與輸出

`pmdata.bin` 不是 JSON 或 Unity 貼圖。此版本的格式由 6 個資料池、76-byte 尾端索引與 12-byte 表格 schema 組成。型別值大於等於 100 時，值從 offset 儲存格向前引用共用常數；若誤當成一般表格位移，座標與布林值會解錯。

新增的 `scripts/pmdata.py` 以資料池邊界、唯一鍵、型別及布林值範圍做結構檢查。`scripts/luajit_constants.py` 只讀取 LuaJIT 常數、數值與指令資料，格式參考 [LuaJIT 官方序列化定義](https://github.com/LuaJIT/LuaJIT/blob/v2.1/src/lj_bcdump.h)。遊戲指令編號與標準版本有差異，不可直接用標準 opcode 表完整反編譯。

| 檔案 | 用途 |
| --- | --- |
| `exports/grab-eggs-data/index.html` | 可離線開啟的互動檢視頁 |
| `exports/grab-eggs-data/candidates.csv` | 全部候選紀錄，可用 Excel 開啟 |
| `exports/grab-eggs-data/maps/<ID>.json` | 每張圖的座標、校準、房間、候選點 |
| `exports/grab-eggs-data/difficulty.json` | 難度 enum、房間類型、原始難度設定與生成參數 |
| `exports/grab-eggs-data/reward-types.json` | 繁體名稱與獎勵類型設定 |
| `exports/grab-eggs-data/monster-types.json` | 僅首領級幽黯星法師的中英文名稱與設定 |
| `exports/grab-eggs-data/display-policy.json` | 地城範圍、單張底圖策略與樓層設定查核 |
| `exports/grab-eggs-data/source-tables.json` | 本次使用的來源資料列；略去編輯者資訊 |
| `exports/grab-eggs-data/source.json` | 封包路徑、資料表位置與來源成員 SHA-256 |
| `exports/grab-eggs-data/bytecode-evidence.json` | 座標與抽選函式的局部靜態證據 |
| `exports/grab-eggs-data/validation.json` | 引用缺口、模板匹配、入口／出口驗證、計數 |
