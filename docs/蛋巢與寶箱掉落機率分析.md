# 蛋巢與寶箱掉落機率分析

## 2026-10-08 網路搜尋與本機更新包複查

結論：**找到部分地面拾取點的道具機率，但仍未找到混沌寶箱逐項道具的可靠百分比。** AniimoTools 對容器獎勵明確註記由伺服器決定；本機最新可用資源也缺少計算開箱機率所需的禮包內容及抽取權重。兩者一致，支持伺服器掌握開箱配置的推論，但此次未接觸伺服器端程式。

### AniimoTools 能查到什麼

- [古代遺物資料庫](https://aniimotools.dev/db/items/ancient-relic/)的地面拾取區有每個拾取點抽取道具的百分比。例如部分植物拾取類型中，古玉靈芝、銀紋鳳蕨等各為 0.03%，虹彩幽蘭與虹彩海鈴各為 0.003%；其他拾取類型會有不同數值。這些是特定地面拾取類型的機率，不能移作混沌寶箱的掉率。
- 同頁 **Containers** 說明同一字母的容器共用獎勵表，內容由伺服器決定，因此沒有列出容器對應道具清單；困難、惡夢、混沌各使用自己的表。
- [地宮地圖](https://aniimotools.dev/map/lost-sanctum/)標示部分鑰匙房蛋巢出現率約 21%–50%，並列出部分守衛生成率。這些數字描述房間／物件生成，無法回答開一個混沌寶箱出現某件道具的機率。
- 另檢查[搶蛋模式說明](https://aniimotools.dev/systems/egg-heist/)與[裝備、天賦及挑戰指南](https://aniimotools.dev/guides/egg-heist/)，未找到混沌寶箱逐項機率表。

### 官方與社群搜尋

[9 月 23 日官方公告](https://www.aniimo.com/newslist/detail/100145)確認混沌的虹光伊莫蛋與琉璃藏品掉率較高，但没有公布百分比。[9 月 30 日官方補丁公告](https://steamcommunity.com/app/4126040/allnews/?l=schinese)提到提高混沌星魔師的星皮果掉率，也沒有列出調整前後數值。[官方機率公示](https://www.aniimo.com/zh-tw/formula-multipliers)涵蓋捕捉、攜帶物頭目掉落與閃耀樣式，未列出混沌開箱機率；其中搶蛋產出蛋的影之閃耀 1% 屬於使用閃耀立方孵化的樣式機率，不能當作寶箱出蛋率。

搜尋亦涵蓋繁簡中文的「混沌、寶箱、掉率、統計」，以及英文 Chaos chest drop rates、loot spreadsheet；找到的玩家討論以場次與個人感受為主，未找到同時列明版本、箱種、開箱分母與各道具出現次數的可重算統計表。

### 最新本機資源的證據

已比對主資源、解開的 `LuaScripts/Common/Data/pmdata.bin` 與本機更新包 `3584014`、`3629693`、`3634150`。主資源及解開檔與 `3634150` 的 pmdata SHA-256 相同：`14552ae57c7d99279ac3791e732ca74ae5dc8cc6db38c01d0e4e0b0134fc77bb`。快取版本文字仍顯示舊版，因此此處以實際檔案雜湊判定資料相同，而未只依快取標籤推定版本。

- 最新資料含 4,977 筆 `drop_data`、1,750 組 `drop_group_data`。
- 三個更新包與主資源各有 **395 個 `drop_package_data` 禮包、652 個子表，非空子表均為 0**。
- 道具群組有道具 ID、數量上下限、條件或子群組引用，但成員欄位沒有 `dropRatio`。例如金色群組 `520005` 的 24 筆成員只有 `index`、`itemId`、`dropMinNum`、`dropMaxNum`；數量上下限為 1 不能推成每件等機率，也不能推成必定各掉一件。

## 結論

- **蛋巢會連到哪一組獎勵，可以確認；各種蛋的名稱、權重與百分比，無法從現有用戶端資料算出。** `rob_egg_chest_data[10]` 在惡夢／混沌分別指向 `drop_data[5002003]`／`[5002005]`，再指向 `drop_package_data[49903]`／`[49905]`。兩個禮包的唯一子表都是空表 `{}`。
- **寶箱有物件品質與不同獎勵群組，但沒有可核實的「開箱取得各道具品質」百分比。** 主要獎勵同樣指向內容為空的隨機禮包。另一組獎勵可追到藍、紫、金色道具清單，但清單沒有足夠資訊證明抽取率或是否必定給予。
- `digong_reward_data` 的惡夢房間 `EggProbability = 0.15`、混沌房間 `0.25` 是地宮生成設定，**不是**打開蛋巢取得某類蛋的 15%／25%。也不能直接當作每個蛋巢候選點的最終生成率。

## 寶箱品質與獎勵鏈

`item_quality` 對應：`3 = 藍色`、`4 = 紫色`、`5 = 金色`、`6 = 琉璃`。`rob_egg_chest_data[*].quality` 是**容器本身**的設定，不是開箱抽出物品品質的機率。地圖工具的「琉璃寶箱」是物件 `2011`（原始名稱「金色石棺」）；其容器 `quality` 仍是 `5`，見 [寶箱分類說明](寶箱分類與圖示大小.md)。

上表的禮包子表也全是 `{}`。`drop_group_data[520004]` 與 `[520005]` 的成員分別可在 `item_data` 查到品質 4 與 5，但群組成員清單不等於掉落百分比。「另一組獎勵」是 `rewardGroup2` 設定；現有資料不足以判斷它在何種條件下發放，或當場會抽到哪個道具。不能從 20／24 個道具 ID 推論均分機率。

## 為何無法計算百分比

目前 `drop_package_data` 共 395 個禮包，**全部**子表均為空；蛋巢與寶箱主要獎勵所需的禮包都在其中。`DropUtils.lua` 的靜態常數顯示掉落邏輯使用 `weightedchoice`、`dropRatio` 和禮包／群組選擇函式，但本機資料沒有這些禮包的實際選項與權重。因此無法核實每種蛋的機率，也無法核實開寶箱得到藍／紫／金／琉璃物品的整體機率。這些值可能保存在未提供給用戶端的資料或由伺服器決定；此處不將該推測當作已確認事實。
