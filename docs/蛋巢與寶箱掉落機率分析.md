## 結論

- **蛋巢會連到哪一組獎勵，可以確認；各種蛋的名稱、權重與百分比，無法從現有用戶端資料算出。** `rob_egg_chest_data[10]` 在惡夢／混沌分別指向 `drop_data[5002003]`／`[5002005]`，再指向 `drop_package_data[49903]`／`[49905]`。兩個禮包的唯一子表都是空表 `{}`。
- **寶箱有物件品質與不同獎勵群組，但沒有可核實的「開箱取得各道具品質」百分比。** 主要獎勵同樣指向內容為空的隨機禮包。另一組獎勵可追到藍、紫、金色道具清單，但清單沒有足夠資訊證明抽取率或是否必定給予。
- `digong_reward_data` 的惡夢房間 `EggProbability = 0.15`、混沌房間 `0.25` 是地宮生成設定，**不是**打開蛋巢取得某類蛋的 15%／25%。也不能直接當作每個蛋巢候選點的最終生成率。

## 寶箱品質與獎勵鏈

## 為何無法計算百分比

目前 `drop_package_data` 共 395 個禮包，**全部**子表均為空；蛋巢與寶箱主要獎勵所需的禮包都在其中。`DropUtils.lua` 的靜態常數顯示掉落邏輯使用 `weightedchoice`、`dropRatio` 和禮包／群組選擇函式，但本機資料沒有這些禮包的實際選項與權重。因此無法核實每種蛋的機率，也無法核實開寶箱得到藍／紫／金／琉璃物品的整體機率。這些值可能保存在未提供給用戶端的資料或由伺服器決定；此處不將該推測當作已確認事實。
