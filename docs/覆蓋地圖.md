# 覆蓋地圖

0.2.9 新增 F1 全域快捷鍵：先開啟地圖模式，按 F1 隱藏，再按恢復；隱藏時可點擊下方遊戲，位置、縮放、篩選與追蹤狀態保留。主視窗最小化時仍可使用。完整關閉地圖模式會釋放 F1。見 [快捷鍵與驗證](覆蓋地圖快捷鍵.md)。

0.2.7 已加入獨立「追蹤」開關，關閉辨識後仍可追蹤，並移除人物路徑線；以下 0.2.6／0.2.4 的實作紀錄保留作歷史參考。現在的操作與驗證見 [獨立人物追蹤](人物追蹤.md)。

按主視窗「地圖模式」才會開啟獨立的覆蓋地圖；主視窗保留，可調整設定或最小化。重新啟動程式不會自動開啟覆蓋地圖。再次按「地圖模式」，或按覆蓋地圖右上 × 都可關閉；關閉主視窗則一起結束。

## 尺寸與操作

使用者提供的 1920 × 1080 圖片，紅框外緣約為 x=2–451、y=494–961，450 × 468 像素。覆蓋視窗採 **448 × 464 實體像素**，預設位於遊戲可繪製區域左上角加 **(4, 496)**；有視窗邊框或在第二台螢幕時，也以遊戲內容區為基準。找不到遊戲時放在目前螢幕左側，並顯示短提示。拖曳地宮編號可以自行調整。

0.2.6 移除背景面板、外框、漸層、工具列及按鈕底色，保留原始地圖、圖示與帶陰影的文字。背景透明不等同於整個視窗滑鼠穿透，地圖仍可拖曳、縮放及操作控制項。

覆蓋地圖會持續跟隨遊戲內容區移動，遊戲縮小時限制於可用範圍內。拖曳地宮編號後，保留本次覆蓋視窗的相對偏移；遊戲最小化或隱藏時收起，還原後跟回。遊戲關閉後等待重新找到遊戲。尚未開遊戲時仍可先開覆蓋地圖，找到遊戲後自動跟隨。關閉再開覆蓋地圖會回到預設相對位置。

- 滾輪以游標位置縮放；拖曳地圖平移；⊞ 讓地圖符合視窗。
- 主視窗與覆蓋地圖同步地宮、難度、品質、類型與補充點。篩選／定位更新不會重設覆蓋地圖的縮放和平移；換地宮才重新符合視窗。
- 覆蓋地圖上的「辨識」與「新一場」會操作主視窗的同一份辨識狀態。
- 若遊戲鎖住滑鼠，先按遊戲提供的 Alt 顯示游標，再操作地圖。覆蓋範圍會接收滑鼠輸入，以支援縮放與點選。
- 建議使用遊戲視窗或無邊框視窗；獨佔全螢幕覆蓋尚未驗證。

主視窗的長提示改成不佔版面的浮動提示，5 秒後消失；完整辨識訊息仍可在側欄查看。本場狀態與「新一場」位於地宮編號旁，滑鼠停在狀態可查看吻合點數。相同本場的定位更新不會反覆延長提示。

## 人物位置

開啟「辨識」，在遊戲按 M，達 200 個吻合點鎖定地宮後，關閉 M 地圖回到遊玩畫面。程式比對左上小地圖與已鎖定地宮，以小地圖中心估計人物位置；成功時顯示青色圓標與軌跡。右下 ◎ 會將人物置中。超過 4 秒沒有新位置，會改成灰色空心「最後位置」；換地宮或按「新一場」會清除。

定位仍是畫面比對估計；迷霧、相似房間、小地圖縮放／旋轉、樓層與連續遊玩準確率仍需實機樣本驗證。使用者這次提供的圖片用於量測覆蓋區域，不能單憑這張外部遊玩畫面驗證地宮內的定位準確率。

## 實作與驗證

`src-tauri/src/overlay.rs` 非同步建立獨立的透明、置頂、無邊框 WebView2 視窗，使用實體像素尺寸；不將主視窗設為其 owner，因此主視窗最小化不應一併隱藏覆蓋地圖。關閉覆蓋視窗不觸發主視窗的擷取 shutdown。原生背景執行緒每 16 ms 讀取快取 HWND 的內容區，只有位置／尺寸改變才以 [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos) 更新，不啟用視窗、不改 Z order；尺寸不變時使用 NOSIZE。找不到遊戲才每秒重新列舉，並驗證 HWND 所屬程序；最小化不會錯誤地切換到其他視窗。手動系統拖曳期间讀取 GUI_INMOVESIZE，暫停跟隨並更新相對偏移。關閉覆蓋或主視窗時停止跟隨執行緒。

前端 `overlay.js` 只接收顯示狀態與傳送操作；`desktop.js` 負責偏好保存與同步，`recognition.js` 和唯一的 Worker 仍在主視窗執行。原生行為參考 [Tauri WebviewWindowBuilder](https://docs.rs/tauri/2.10.3/tauri/webview/struct.WebviewWindowBuilder.html)。

測試使用隔離的 `ANIIMO_TEST_DATA_DIR`、隱藏正式 EXE 及本機 CDP，不改動使用者設定。

### 0.2.6 驗證

- 12 項 Rust 測試、11 項辨識核心測試通過；新增相對移動、手動偏移及縮小／還原的幾何驗證。
- 用螢幕外的原生測試視窗（`scripts/tests/overlay-game-fixture.rs` 編譯為隔離資料夾的 `Aniimo.exe`）驗證真實跟隨迴圈，沒有移動使用者的遊戲。三次位置變更約 26–30 ms 跟上；500 × 500 內容區下正確限制位置，最小化時不跳到 Windows 最小化座標，還原後跟回。此為本機測試時序，不是延遲保證。
- 真實 WebView2 的 `overlay-render-browser.js` 驗證 60 次人物更新與 hover 不重畫固定圖層，置中、縮放及篩選會正確更新快取。該次繪圖測試每次更新平均約 0.03 ms、最高 0.9 ms，僅量測 JavaScript 繪圖提交時間，不代表遊戲幀率或 GPU 完成時間。
- 覆蓋容器、工具列、控制項背景的 alpha 均為 0，canvas 同時保留透明像素與非空白地圖。無人物位置時按鈕使用一般游標，有位置時可置中。
- 原有覆蓋視窗尺寸、地圖與篩選同步、位置過期、新一場及關閉控制回歸檢查通過。

結果保存在 `dist/follow-verification-0.2.6.json`。隱藏測試視窗不會實際顯示，最小化／還原測試確認幾何暫停與恢復；顯示隱藏的視覺效果、真實遊戲長時間負載及獨佔全螢幕仍待實機測試。原始 hover 的 busy 游標已由 CSS 重現，但不能據此宣稱已確認所有遊戲卡頓的原因。
