# 0.1.1 地圖名稱與圖示來源

`20036` 原先顯示的 `3(上左下假路)` 取自參考圖片檔名，並不是遊戲名稱。遊戲資源版本 `3595896` 的 `scene_data[20036].name` 是內部名稱 `抢蛋大作战_随机地宫036`。目前選單與標題統一顯示 `地宮 20036`，其餘 30 張圖同樣僅用地宮編號識別。參考圖檔名只保留在解析／比對紀錄，可攜版資料不再收錄。

標記圖片直接讀取本機遊戲封包的 Texture2D 並輸出 PNG，不重新繪製或改色。圖示同時用於地圖、側欄圖例與點選明細，並隨可攜 EXE 內嵌。來源與 SHA-256 記錄於 `exports/grab-eggs-data/marker-icons.json`。

| 類型 | 遊戲設定與素材 |
| --- | --- |
| 蛋巢 | `rob_egg_chest_data[10].markConfigId = 1014` → `Img_Map_Mark_GrabEgg_Lair.png` |
| 一般寶箱 | 獎勵設定的 `icon` → `UI_Icon_MarkPoint_Chest.png` |
| 高級寶箱 | 有 `markConfigId = 1013` 的寶箱 → `UI_Icon_MarkPoint_TreasureChest.png`，依每個點位的物件類型判斷 |
| 陶罐、其他搜刮點 | 遊戲獎勵設定同樣指定 `UI_Icon_MarkPoint_Chest.png`，未找到這些物件在該設定中的獨立圖示 |
| 入口 | `default_map_mark_data[1009].icon` → `Img_Map_Mark_Uderground_Front_Door.png` |
| 出口 | `default_map_mark_data[1008].icon` → `Img_Map_Mark_Uderground_Begin.png`；依設定對應，不依英文檔名猜測方向 |
| 藍／紫／橙鑰匙 | `default_map_mark_data[1996/1997/1998].icon` → 相應的 `Img_Map_Mark_Uderground_Key_*.png` |

10 張原始圖示覆蓋全部 11 個篩選類型及 12,801 筆候選紀錄。陶罐與其他搜刮點仍可透過分類開關分別篩選、點選查看名稱。虛線補充點外圈與選取外圈保留，用於說明候選來源與目前選取狀態。

重新產生資料：執行 `scripts/parse_dungeon_data.py`，會連同圖示一起匯出。重新打包：執行 `scripts/build_portable.ps1`，只讀取已匯出的圖片，不需要再次存取遊戲。

## 0.2.10 應用圖示與 favicon

使用「珍藏·不朽晶鑽蛋」（藏品 ID `5900509`）的原圖 `ui_item_Grabegg_DiamondEgg_Pink.png`。詳見 [藏品解析](鑽石蛋藏品解析.md)。

![應用圖示](../app/src-tauri/icons/icon.png)

- `app/src-tauri/icons/icon.png`：256 × 256 RGBA，與匯出原圖逐位元組相同，保留透明背景。
- `app/src-tauri/icons/source.json`：遊戲資源版本、資源路徑、封包雜湊與 PNG SHA-256。
- `app/src-tauri/icons/icon.ico`：16、24、32、48、64、128、256 px，供 Windows EXE 與視窗使用。
- `favicon.png`／`favicon.ico`：同時複製到 `app/frontend` 與 `exports/grab-eggs-data`，主頁及覆蓋視窗均宣告 favicon。

兩個建置入口共用 `scripts/app_icons.py`；`prepare_portable.py` 已移除舊圖示的重繪程式，因此重新打包不會還原舊圖示。

驗證：Release x64 編譯成功；直接讀取最終 EXE 的七個 Windows 圖示資源，均與新 ICO 對應影像的 SHA-256 相同。以隔離設定啟動最終 EXE，經 agent-browser 檢查實際 WebView2：PNG／ICO 均能載入及解碼，PNG 雜湊與珍藏款原圖一致，31 張地圖選項正常，覆蓋頁面亦宣告兩種 favicon，未記錄頁面錯誤。紀錄為 `dist/icon-verification-0.2.10.json` 與 `dist/icon-browser-verification-0.2.10.json`。
